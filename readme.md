2025年5月版本：

1.**起因**：本地通过DeepSeek手搓了一个简易版本的SDS，那时候我还不知道API是什么，一切知识来自于测试反馈。我就在本地windows电脑里面测试与学习。我尝试找DeepSeek的原对话，但是好像找不到了。只留有后面想离线云端的升级版本思路。

本地能跑之后，想搬到一台有 GPU 的服务器上，再让 iOS 调用它。我知道有个叫 Docker 的东西，就像打包一个野餐包——本地装好的东西全塞进去，到那边打开就能用。

**第一次被岔开**：要先写个 Dockerfile，我不会写，让它生成。生出来一个十几 G 的包，我觉得太大，才知道还有个 `.dockerignore`。

**然后卡在打包上**：`docker build` 一直失败。原因不是代码，是国内网络拉不下来东西。阿里云加速器、清华源、中科大源——一个环节一个环节地通。

**打包成功，上传又不行**：我本来以为用 `scp` 就够了。但 SSH 能连、`scp` 不能用。**这台服务器不是我以为的那种服务器**，它不给你开端口，传文件得先走 OSS 中转。上传的时候我还往内网 IP 上推，ping 了半天不通，才反应过来要用公网 IP。

**要命的一步**：镜像传上去了，**服务器不支持 Docker**。整条打包链路白做一遍。只能从头手搭环境：下 Python 源码、编译、建虚拟环境、装依赖、下模型。模型下载还被墙，又换成华为云源。

**这些坑挨个填完之后**，才轮到真正的目标——把 iOS 和服务端连起来。

**我当时的想法**：两边都跑起来了，那我改一下 iOS 里的地址，指到服务器的公网 IP，应该就通了。

**结果不通**。iOS 报一个 ATS 的错。我以为是我没配好 iOS，就去改 `Info.plist`：加例外、清 Xcode 缓存、重启、换写法……**改了五轮，一模一样的错**。

**直到我停下来想了一下整件事**：我一直盯着 iOS 那头，因为报错在那边。但我用 `netstat` 查的时候，服务端**根本没有在监听**。

**然后我想起了一件我早就知道的事**：这台服务器 SSH 能连、`scp` 不行、传文件要走 OSS、控制台里我**从来没见过"安全组"这一项**。

**那一刻就明白了**：不是 iOS 配错了，也不是我代码写错了。是**这台机器根本不允许外面连进来**。

**于是停在这里**。服务器也快到期了。没改成，那时候还不知道哪里出现了错误。
